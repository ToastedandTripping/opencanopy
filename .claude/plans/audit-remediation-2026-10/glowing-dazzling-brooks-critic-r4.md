Load-bearing defects behind the verdicts

The guard bootstrap is not closed. C3 says “Every behaviour guard is then run against that deploy, which has the probe but not the fix” (195–198). That is true for M1a's fixes, not S0's. S0 precedes batch 0 in the graph. A successful negative control for S0 cannot be produced by testing a deployment that already contains S0. The generic alternative for “pure regression guards” does not cover newly repaired S0 defects unless the contract explicitly assigns them to controlled-revert drafts. In addition, M1a's search oracle is a “reference capture of the target view taken by direct deep link” (539), while broken cold deep links are a central defect. State how the baseline camera is independently positioned and verified; otherwise the supposedly independent oracle can record the same wrong landing view. A verified manual positioning step on the instrumented baseline or a separate test fixture would resolve this without widening implementation scope.

The privacy release has an old-client gap. The inspected `origin/main:public/tracker.js` retains its functions in an IIFE, sends `window.location.href` in `trackPageView`, installs click/unload listeners, and exposes `window.analyticsTracker.trackPageView`. Deploying a replacement script does not replace those functions in an existing tab. Old code can continue submitting coordinate-bearing fields after S0 passes its fresh-browser test. The plan already recognizes old-tab limitations for image assets; it must recognize them for the tracker too. Separately, “Lee owns them” (348) identifies an owner, not the endpoint's read access, credential boundary, retention, backups, or evidence-export exposure. This review does not authorize deletion: the explicit human disposition decision should remain, with verified access and a bounded decision/implementation state.

The area contract is a migration, not just a definition. Replacing summed areas with first-recorded dissolved areas can change totals and attribution. The plan names consumers but supplies no S1-lite release bundle for switching them together, and no declared period of version coexistence. Adding consumers in later child plans cannot satisfy a program contract that says every consumer already reads v1. The calculator freeze makes this especially concrete. Resolve the exception and version boundary in the program so child plans have a possible acceptance condition.

Three stress tests

Pre-mortem — It is three months later and the program failed:

1. Type-specific worst case: OpenCanopy presents a polished, apparently verified but geographically false forest-loss story, while public surfaces disagree about harvested hectares. S1-lite's new total passes its aggregate test, but spatial placement and older map/calculator consumers were never migrated together. The warning was a scalar truth check and an all-consumers promise without release ownership.
2. Location-bearing analytics still arrive after the privacy release. Fresh-context sentinel tests pass, but old tabs keep executing the previous tracker and the collector accepts it. Historical data remains accessible under unverified permissions. The warning was treating deployment as revocation of code already running in visitors' browsers.
3. The first relay blocks on an impossible baseline, or the team waives it informally. S0 is already fixed by the time the required instrumented baseline exists; later a coordinator restart leaves a candidate pending while another lane proceeds. The warnings were a universal guard rule inconsistent with the graph and durable records without a restart/ownership protocol.

Load-bearing assumptions — confidence and consequence:

- The instrumented baseline is pre-fix for every behaviour guard: LOW; contradicted for S0 by the graph. Consequence: negative controls cannot prove the specified fixes. Resolve before implementation by assigning baseline/control type per early release.
- Client-only sanitization closes the location leak: LOW for existing tabs; the inspected tracker explains why. Consequence: ongoing collection despite a green privacy test. Resolve the collector boundary or explicitly accepted residual exposure before claiming remediation.
- All area consumers can adopt v1 at S1-lite while the calculator remains unchanged: LOW; the contracts conflict. Consequence: incompatible public totals or an unapproved calculator change. Resolve the migration and exception before S1-lite planning.
- A single human pusher and surviving coordinator serialize releases: MEDIUM; human ownership reduces collision probability, but session loss and stale ledger reads remain unspecified. Consequence: candidate attribution and rollback targets can become ambiguous. Establish takeover and claim rules before overlapping lanes publish.

Inversion — Rejected alternative (1), writing every relay plan now, wins only if interfaces and data contracts are stable enough to avoid widespread rework; the map changes and stale August plans show that condition is not met. However, a narrower up-front integration/migration specification already wins: release identity, S0 baselines, tracker ingress, and shared area consumers cross relay boundaries and cannot safely be settled independently just in time. Rejected alternative (2), folding everything into B–E, would win if fixes were inseparable from those phases; the independent live privacy and story defects do not establish that. Keep the program decomposition, but settle those cross-relay contracts first.

Overall verdict: FAIL — the gate should remain blocked. The plan now contains substantial concrete controls, but its S0 verification baseline cannot work in the prescribed order, its scope waiver no longer describes the work, and its universal area-consumer contract conflicts with the calculator freeze. The privacy fix also lacks protection or an explicit residual-exposure decision for old clients and lacks verified stewardship of stored coordinates. These are current contradictions and uncovered paths, not reasons to reopen Lee's accepted dollar-bar decision or demand fully detailed distant-phase plans.
