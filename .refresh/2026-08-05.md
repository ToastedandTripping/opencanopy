## What was deliberately left (the "no" list)

- **MapLibre 6.x upgrade** -- major version, behavior-changing (WebGPU backend, rendering changes), needs react-map-gl compat check + visual regression testing. L effort, not a cleanup.
- **Style-load guard unification** -- 4 implementations (SatelliteLayers, PmtilesLayers, WfsLayers, visibility.ts) work correctly today; PmtilesLayers has a fragile split-cleanup path. Unifying risks introducing regressions in the most sensitive code (map layer lifecycle). Better as a targeted relay.
- **WFS outline honor registry style.outline** -- latent inconsistency but no current consumer affected (all outline-bearing layers are tile-backed). Documented CAVEAT in types/layers.ts is accurate.
- **Visibility toggle shared helper** -- M effort, touches DataLayer.tsx lifecycle management. Payoff < risk.
- **Hash-parsing dedup (useLayerState + useMapState)** -- would add reverse coupling between the two hooks. The duplication is 5 lines.
- **Barrel/import consistency** -- cosmetic, no behavior impact.
- **MapLike/VisibilityMap interface merge** -- test-support types in story/, low impact.
- **initPMTiles double-call** -- idempotent by design, routes never co-exist.
- **Terrain source registration dedup** -- story/map deliberately separate paths.
- **MAPTILER_KEY centralize** -- registry.ts reads the env var at module scope for satellite URL construction; importing from mapConfig would add a dependency-order constraint for low payoff.
- **Stale .claude/plans/** -- 127KB orphaned artifacts from shipped relays. Deleting commits new git objects but doesn't save repo space (still in history).
- **Dead pipeline scripts** (build-tiles-chunked.sh, build-v10-throttled.sh) -- may be useful for manual tile rebuilds on constrained machines. Not part of the documented pipeline but not harmful.
- **react 19.2.4 -> 19.2.8** -- patch level, minimal value this pass.
