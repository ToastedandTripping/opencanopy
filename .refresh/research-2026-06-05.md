## Top recommendations (cross-cutting, ranked by value ÷ effort)

1. **Add an Open Graph / Twitter preview image** — *highest value, lowest effort.* OpenCanopy's signature feature is "every view is a link" (shareable `#lat&lng&z&layers` URLs), but `layout.tsx` sets OG **title/description only — no image**. Social/Slack/journalist bots don't run JS, so a shared map link currently previews as a blank card → far fewer clicks. A single static OG image (or a small set per preset) is a few lines. Connects directly to the advocacy mission. ([Next.js OG](https://nextjs.org/docs/app/getting-started/metadata-and-og-images), [prerender.io](https://prerender.io/blog/benefits-of-using-open-graph/))
2. **Ship an embeddable view** (`/map?embed=1` → chromeless iframe with locked params). Every comparable tool (Atlas, ArcGIS, BatchGeo) offers this; it's how advocacy/journalism maps actually spread. The share-URL infra already exists — embed is a thin layer on top. ([Atlas embed](https://atlas.co/blog/embedding-interactive-maps-on-your-website-a-simple-guide/), [ONS interactives](https://digitalblog.ons.gov.uk/2022/02/15/embedding-ons-interactives-in-your-website/))
3. **Per-layer opacity + reorder in the layer panel** — the single biggest UX gap vs Global Forest Watch, whose legend lets users reorder, set per-layer opacity, and date-filter. OpenCanopy has presets + on/off; opacity/reorder is what makes multi-layer comparison legible. ([GFW interface](https://nature4climate.org/new-map-interface-on-global-forest-watch-makes-it-easier-to-use-and-customize-forest-data/), [GFW help](https://www.globalforestwatch.org/help/map/))
4. **Evaluate MapLibre Tile (MLT) for the dense layers** — the MLT spec went **stable Oct 2025**: ~3× better compression than MVT, up to 3× faster decode, built for planet-scale 2D basemaps. This is the structural answer to the forest-age (6.2M) / conservation-priority (258K) rendering cost that we currently paper over with raster overviews + minZoom gates. Track adoption maturity before committing. ([MLT spec](https://github.com/maplibre/maplibre-tile-spec), [MLT paper](https://arxiv.org/html/2508.10791v1))
5. **Add 2–3 high-value BC layers** under OGL-BC (commercial + redistribution OK, compatible with the project's licensing): **Caribou herd locations**, **Forest Biodiversity Value**, **old-growth condition reports**. High mission relevance, same WFS/tile pipeline. ([BC Data Catalogue](https://catalogue.data.gov.bc.ca/), [Forest Biodiversity Value](https://www2.gov.bc.ca/gov/content/environment/natural-resource-stewardship/cumulative-effects-framework/value-assessments-protocols/forest-biodiversity))

## Axis A — Performance & rendering

**Findings**
- **MLT (MapLibre Tile) is stable as of Oct 2025** — 3× compression, 3× faster decode vs MVT, 6× on large tiles. Designed for exactly OpenCanopy's pain (millions of forest polygons). The hot path that matters most — PB tile data → WebGL buffers — is what MLT optimizes. ([MLT](https://github.com/maplibre/maplibre-tile-spec), [arxiv](https://arxiv.org/html/2508.10791v1))
- **MapLibre large-data guidance**: convert GeoJSON → vector tiles (done), set source `maxzoom` lower (~12 is the sweet spot — OpenCanopy uses `PMTILES_MAX_ZOOM=12`, good), cluster point layers (species-at-risk already clusters). ([MapLibre large-data](https://maplibre.org/maplibre-gl-js/docs/guides/large-data/))
- **PMTiles**: sparse pyramids + the "two-layer" pattern (aggressively simplified overview + detail layer) — OpenCanopy already does raster-overview + vector split, which is the right shape. Caveat worth knowing: *variable overzoom on sparse PMTiles is under-specified across renderers* — relevant if we lean harder on minZoom-gated sparse layers. ([Protomaps PMTiles](https://docs.protomaps.com/pmtiles/), [overzoom discussion](https://github.com/protomaps/PMTiles/discussions/321))
- **Bundle**: the 1 MB maplibre-gl chunk is the WebGL floor (~300 KB gzip) and is correctly deduped across react-map-gl. Next.js dynamic imports already cut first-load; the story dynamically imports its heavy components. ([Next bundling](https://nextjs.org/docs/app/guides/package-bundling), [dynamic imports](https://thekevinwang.com/2021/03/15/reduce-first-load-js))

**Recommendations**: (1) put MLT on the watch-list for the next tile-pipeline rebuild — don't migrate yet, but it's the real fix for the dense-layer cost the audit flagged. (2) The conservation-priority 258K layer (production WARN) is a candidate for a raster overview like forest-age, *or* an MLT pilot. (3) Already-good: maxzoom, clustering, raster/vector split, dedup.

## Axis B — UX & comparable maps

**Findings**
- **Global Forest Watch** (the reference implementation, by Vizzuality): legend panel supports **layer reorder, per-layer opacity, date filtering**, base-layer switching, and region-scoped data. OpenCanopy has presets + on/off + a timeline, but not opacity/reorder. ([GFW UX](https://nature4climate.org/new-map-interface-on-global-forest-watch-makes-it-easier-to-use-and-customize-forest-data/))
- **Scrollytelling (mobile)**: mobile-first; **keep-scrolly vs stack** decision (keep scroll when transitions are meaningful — OpenCanopy's year-by-year cutblock animation qualifies); larger touch targets; **passive event listeners for touch/wheel to prevent scroll jank**; AVIF/WebP + lazy-load. ([Pudding responsive scrolly](https://pudding.cool/process/responsive-scrollytelling/), [mobile scroll UX](https://www.portotheme.com/designing-for-the-impatient-scroll-7-mobile-ux-rules-you-should-actually-care-about-in-2025/))

**Recommendations**: (1) per-layer opacity + reorder (rec #3 above). (2) Verify the story uses passive listeners and test it at 375px — ties to the production a11y/mobile WARN. (3) Consider GFW-style "compare two layers" affordance for the accountability story (cutblocks vs old-growth).

## Axis C — Data expansion

**Findings**
- **BC Data Catalogue** (DataBC, CKAN) under **Open Government Licence – B.C.** — permits commercial use + redistribution, compatible with OpenCanopy's AGPL/CC-BY-SA. Same WFS access pattern the app already uses. ([DataBC](https://www2.gov.bc.ca/gov/content/data/about-data-management/databc), [catalogue](https://catalogue.data.gov.bc.ca/))
- High-value candidates by mission fit: **Caribou herd locations** (charismatic at-risk species; pairs with the existing species layers), **Forest Biodiversity Value** (a provincial value-assessment raster — strong "what's worth protecting" framing), **old-growth condition reports** by Natural Resource District. ([caribou](https://catalogue.data.gov.bc.ca/dataset/caribou-in-british-columbia), [forest biodiversity](https://www2.gov.bc.ca/gov/content/environment/natural-resource-stewardship/cumulative-effects-framework/value-assessments-protocols/forest-biodiversity))

**Recommendations**: each new layer is "one config object in registry.ts" (the project's stated pattern) + a WFS/proxy entry + optional tile build. Prioritize Caribou (visual, emotional, complements species-at-risk) and Forest Biodiversity Value (reframes the map from "what's being lost" to "what's worth keeping"). Validate feature counts against the province-scale crash guard (the new minZoom primitive) before enabling.

## Axis D — Reach & impact

**Findings**
- **OG images are load-bearing for distribution**: bots don't run JS, so client-side meta won't work; a missing OG image means link previews show no image → "significantly fewer clicks." OpenCanopy ships OG title/description but **no image**. For a visual map whose core feature is shareable links, this is the cheapest high-leverage fix available. ([Next OG](https://nextjs.org/docs/app/getting-started/metadata-and-og-images), [OG benefits](https://prerender.io/blog/benefits-of-using-open-graph/))
- **Embeds drive adoption** by orgs/journalists; standard pattern is an iframe with locked params. ([Atlas](https://atlas.co/blog/embedding-interactive-maps-on-your-website-a-simple-guide/))
- Scrollytelling/SEO: scroll content still needs the SEO basics (accessibility, load speed, structure) — reinforces the production a11y WARN. ([scrolly SEO](https://www.krishaweb.com/blog/what-is-scrollytelling/))

**Recommendations**: (1) static OG image now; (2) consider a small build-time OG generator keyed off preset (`?preset=threats` → a themed card) once the static one ships — but a static export can't generate OG per arbitrary share-URL at request time, so a curated set beats dynamic here; (3) `/map?embed=1` chromeless mode; (4) the privacy-notice WARN (production audit) intersects here — a footer with privacy + data-source attribution also serves discoverability/credibility.
